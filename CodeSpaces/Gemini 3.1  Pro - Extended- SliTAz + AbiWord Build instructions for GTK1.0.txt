In the builder, ensure you include packages for an X server (like xorg-server or tinyx).

Crucially, you must also include the build tools necessary to compile software from source (slitaz-toolchain, gtk+-dev, wget, tar).

Rename the downloaded file to tiny-slitaz.iso and place it in a new, empty folder on your Linux machine.

2
Run the Remastering Script
Extracts, compiles, and repacks the ISO
Save the following code as build-iso.sh in the same directory as your tiny-slitaz.iso. Make it executable (chmod +x build-iso.sh) and run it with sudo ./build-iso.sh.

Bash
#!/bin/bash
# -------------------------------------------------------------
# Tiny SliTaz + X Server + AbiWord 1.0 Remastering Script
# -------------------------------------------------------------

# 1. Prepare directories
mkdir -p mnt new-iso rootfs

# 2. Mount and extract the base ISO
echo "Extracting base ISO..."
mount -o loop tiny-slitaz.iso mnt
cp -a mnt/* new-iso/
umount mnt

# 3. Unpack the root filesystem (initramfs)
echo "Unpacking root filesystem..."
cd rootfs
# SliTaz initramfs is usually lzma or gzip compressed. We'll handle both.
if gzip -t ../new-iso/boot/rootfs.gz 2>/dev/null; then
    zcat ../new-iso/boot/rootfs.gz | cpio -idm
else
    unlzma -c ../new-iso/boot/rootfs.gz | cpio -idm
fi

# 4. Bind mounts for the chroot environment
mount -t proc proc proc/
mount -t sysfs sys sys/
mount -o bind /dev dev/
cp /etc/resolv.conf etc/resolv.conf

# 5. Chroot into the filesystem, download, compile, and install AbiWord 1.0
echo "Entering chroot to compile AbiWord..."
chroot . /bin/sh << 'EOF'
# Create build directory
mkdir -p /src
cd /src

# Download AbiWord 1.0 from the specified mirror
wget -r -l1 -nd -A "abiword-1.0*.tar.gz" https://mirror.ontdb.com/gnome/sources/abiword/1.0/
tar -xzf abiword-1.0*.tar.gz
cd abiword-1.0*

# Configure, compile, and install
./configure --prefix=/usr
make
make install

# Clean up to keep the final ISO tiny
cd /
rm -rf /src
tazpkg clean-cache
EOF

# 6. Clean up chroot mounts
rm etc/resolv.conf
umount proc
umount sys
umount dev

# 7. Repack the Root Filesystem
echo "Repacking root filesystem..."
find . -print | cpio -o -H newc | gzip -9 > ../new-iso/boot/rootfs.gz
cd ..

# 8. Create the new bootable ISO
echo "Generating final bootable ISO..."
genisoimage -R -l -b boot/isolinux/isolinux.bin -c boot/isolinux/boot.cat \
  -no-emul-boot -boot-load-size 4 -boot-info-table \
  -V "TinySliTaz-Abiword" -o tiny-slitaz-abiword-final.iso new-iso/

echo "Done! Your bootable image is: tiny-slitaz-abiword-final.iso"

A Critical Note on Compiling
AbiWord 1.0 was released in 2002. Compiling a 20+ year-old C++ codebase on a modern compiler (like the one found in current SliTaz toolchains) will almost certainly result in compilation errors during the make step due to changes in C++ standards. Furthermore, AbiWord 1.0 relies strictly on GTK+ 1.2 and glib 1.2, which have been obsolete for decades and are no longer in modern repositories.

If the script fails during the make step inside the chroot, you will either need to downgrade your Tiny SliTaz base to an ancient version (circa 2008) that still supports GTK+ 1.2, or heavily patch the AbiWord 1.0 source code to comply with modern GCC and GTK+ 2/3.
